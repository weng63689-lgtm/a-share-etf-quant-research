# 第七步：交易成本与容量模型

版本日期：2026年10月29日

## 本步解决什么问题

前一步解决了“制度上能否交易”，但按开盘价原价成交仍会高估策略收益。本步为每笔订单加入：

- 佣金费率。
- 最低佣金。
- ETF印花税。
- 过户费。
- 基础滑点。
- 按订单占当日成交额比例计算的市场冲击。
- 单日最大成交参与率。
- 1倍、2倍、3倍成本压力。

成本参数位于 `configs/default.yaml` 的 `costs` 部分，不应把当前示例参数视为中信证券最终费率。

## 当前参数

| 参数 | 当前值 | 说明 |
|---|---:|---|
| 佣金率 | 0.03% | 待券商确认 |
| 最低佣金 | 5元 | 待券商确认 |
| ETF印花税 | 0 | 按ETF当前研究假设设置 |
| 过户费 | 0 | 待正式交易规则确认 |
| 基础滑点 | 2个基点 | 买卖方向分别不利成交 |
| 冲击系数 | 5个基点 | 在1%成交额参与率下的参考冲击 |
| 冲击指数 | 0.5 | 冲击随参与率按平方根增长 |
| 最大日成交参与率 | 10% | 超过时拒绝整笔订单 |
| 压力倍数 | 1、2、3倍 | 用于成本敏感性测试 |

最低佣金、印花税和交易权限必须在模拟或实盘前按券商合同和交易所现行规则核对。

## 成交价格

先计算基础滑点和市场冲击：

```text
参与率 = 订单金额 / 当日成交额
冲击基点 = 冲击系数 × (参与率 / 参考参与率) ^ 冲击指数
调整比例 = (基础滑点 + 冲击基点) × 压力倍数 / 10000
```

然后按买卖方向调整：

```text
买入成交价 = 市场价 × (1 + 调整比例)
卖出成交价 = 市场价 × (1 - 调整比例)
```

ETF最小价格变动单位为0.001元。买入价格向上取整，卖出价格向下取整，避免成本模型产生优于市场的成交价。

## 费用

```text
佣金 = max(成交金额 × 佣金率 × 压力倍数, 最低佣金)
印花税 = 成交金额 × 印花税率 × 压力倍数
过户费 = 成交金额 × 过户费率 × 压力倍数
总成本 = 佣金 + 印花税 + 过户费 + 滑点和冲击成本
```

买入费用计入持仓成本；卖出费用从卖出回款中扣除。账户流水新增 `fees` 字段，保存每笔实际费用。

## 成交容量

```text
最大可成交金额 = 当日成交额 × 最大参与率
```

当前若目标数量超过容量，整笔订单被拒绝，并返回 `LIQUIDITY_CAPACITY_EXCEEDED`。这是保守的日频假设，后续可以增加部分成交和跨日订单管理。

## 真实行情压力测试

对六只ETF的最近可交易日期分别测试5万元和50万元订单，并计算买卖两个方向：

| 成本压力 | 平均买入成本 | 平均卖出成本 |
|---|---:|---:|
| 1倍 | 7.00个基点 | 7.00个基点 |
| 2倍 | 12.63个基点 | 12.62个基点 |
| 3倍 | 17.14个基点 | 17.12个基点 |

共生成72个成本场景。平均值同时包含佣金、最低收费、滑点、冲击和价格取整，不能只按佣金率估算实际交易成本。

## 运行命令

执行成本与容量压力测试：

```powershell
uv run quant-cost audit
```

查看最近一次结果：

```powershell
uv run quant-cost summary
```

## 输出文件

- `data/processed/cost_model_scenarios.parquet`：逐笔成本测试场景。
- `data/processed/cost_model_audit.json`：参数、汇总和压力测试结果。
- DuckDB表`cost_model_scenarios`：供策略回测查询和筛选。

## 验收标准

- 小额订单正确触发最低佣金。
- ETF默认印花税为0。
- 买入成交价高于市场价，卖出成交价低于市场价。
- 2倍和3倍成本压力必须高于1倍。
- 超过日成交参与率的订单必须被拒绝。
- 订单成交后，现金变化包含佣金和其他费用。
- 买入费用进入持仓成本，卖出费用减少已实现利润。

## 当前边界

当前成本模型尚未区分：

- 中信证券实际佣金、最低收费和账户等级。
- 盘中流动性变化与订单分拆。
- 大额订单对后续价格路径的永久冲击。
- 申报、撤单、交易所流量费和接口费用。
- 部分成交和跨日剩余订单。

第一版动量轮动策略和无成本、1倍、2倍、3倍成本回测已在第八步完成。
