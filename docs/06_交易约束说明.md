# 第六步：ETF交易约束

版本日期：2026年10月29日

## 本步解决什么问题

第五步证明账户能够正确记账，但没有判断一笔委托是否真的可以成交。本步把以下A股场内ETF约束接入订单执行：

- 信号在交易日收盘后产生，最早在下一交易日成交。
- 买入数量按100份取整。
- 当日买入的份额不能当日卖出，下一交易日起可卖。
- 没有当日行情或成交量为0时，不假设可以成交。
- 开盘已经在涨停价时，保守拒绝买单。
- 开盘已经在跌停价时，保守拒绝卖单。
- 股票ETF通常为10%涨跌幅，科创板ETF和适用新规的创业板ETF为20%。

本步仍不加入佣金、滑点、市场冲击和成交量容量限制。订单成交价暂时使用下一交易日开盘价。

## 生效日期规则

交易规则保存在 `configs/trading_rules.csv`，每只ETF可以根据日期拥有不同规则。这样不会把2026年的规则错误应用到2012年。

当前规则：

| ETF | 生效区间 | 涨跌幅 | 结算 |
|---|---|---:|---|
| 510050 | 2012年起 | 10% | T+1 |
| 510300 | 2012年起 | 10% | T+1 |
| 510500 | 2012年起 | 10% | T+1 |
| 512100 | 2012年起 | 10% | T+1 |
| 588000 | 2012年起 | 20% | T+1 |
| 159915 | 2012-01-01至2020-08-23 | 10% | T+1 |
| 159915 | 2020-08-24起 | 20% | T+1 |

规则表还包含最小价格变动单位和买卖整手数量。正式交易前仍需通过交易所和基金公告复核。

## 成交判断顺序

一笔日频订单按以下顺序检查：

1. 委托方向、数量是否有效。
2. 执行日期是否晚于信号日期。
3. 当日是否有行情，成交量和成交额是否大于0。
4. 卖出是否已有持仓，且份额是否已满足T+1。
5. 买入是否满足整手规则；卖出是否满足整手或零股清仓规则。
6. 是否存在前一收盘价。
7. 开盘价是否已经位于涨停或跌停。
8. 现金是否足够，以及账户是否还有其他错误。

任一检查失败，订单返回`REJECTED`及明确原因，不会修改账户持仓。

## 公司行动日的参考价

份额折算当天，原始价格会按折算倍数变化。如果直接使用前一日原始收盘价计算涨跌停，会误判为异常涨跌。

程序先按以下逻辑还原行情参考价：

```text
股本折算后参考价 = 前一日收盘价 / 份额调整倍数
分红调整后参考价 = 参考价 - 每份现金分红
```

之后再计算涨停价和跌停价。本次扫描中，3次真实份额折算日经过修正后不再被误判为涨跌停。

## 真实历史扫描结果

当前六只ETF的历史日线发现13个需要拦截的事件：

| 约束事件 | 数量 |
|---|---:|
| 开盘涨停 | 4 |
| 开盘跌停 | 1 |
| 成交量为0 | 4 |
| 缺失行情或疑似停牌 | 4 |

扫描只说明这些日期需要特殊处理，不代表当天一定完全无法成交。开盘到达涨停价并不等同于全天封板，当前策略采用保守假设，避免高估成交率。

## 运行命令

执行交易规则与历史约束扫描：

```powershell
uv run quant-execution audit
```

再次查看最近一次扫描摘要：

```powershell
uv run quant-execution summary
```

## 输出文件

- `configs/trading_rules.csv`：带生效日期的交易规则。
- `data/processed/trading_constraint_events.parquet`：历史涨跌停、零成交和缺失行情事件。
- `data/processed/trading_constraint_report.json`：扫描结果汇总。
- DuckDB表`trading_constraint_events`：供后续回测撮合查询。

## 验收标准

- 同日卖出刚买入的ETF必须失败。
- 下一交易日可以卖出前一日已结算份额。
- 无行情或成交量为0时必须拒单。
- 买入整手不足时必须拒单。
- 开盘涨停时买单必须失败，开盘跌停时卖单必须失败。
- 份额折算日的价格限制不能误用原始前收盘价。
- 红绿修正后的规则必须覆盖全部候选ETF。
