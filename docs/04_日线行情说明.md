# 第四步：候选ETF日线行情

版本日期：2026年10月29日

## 本步解决什么问题

第三步只有ETF名单和交易日历，还不能计算收益、趋势或动量。第四步为候选池中的六只ETF下载历史日线，并把不同数据来源的字段整理成固定格式。

本步同时保留两套价格：

- 未复权价格用于之后模拟真实成交、整手数量和账户估值。
- 前复权价格用于计算历史收益、动量和波动率，减少分红对价格序列的影响。

原始响应、清洗结果和质量报告分开保存，任何一份回测数据都可以追溯来源和抓取时间。

## 数据流程

```text
AKShare未复权日线 + 前复权日线
             ↓
检查日期集合是否一致
             ↓
按symbol和trade_date合并
             ↓
检查交易日缺口、OHLC、价格跳变和最新日期
             ↓
只有全部通过才替换etf_daily
```

如果某只ETF下载失败，或者任何关键质量检查失败，旧的 `etf_daily` 不会被覆盖。程序会返回非零状态，防止后续策略读到半成品数据。

## 统一字段

策略代码只使用以下稳定字段，不直接读取AKShare的中文列名：

| 字段 | 含义 |
|---|---|
| `symbol` | 六位ETF代码 |
| `exchange_symbol` | 带交易所后缀的代码，例如 `510300.SH` |
| `trade_date` | 交易日 |
| `open/high/low/close` | 未复权开高低收 |
| `volume` | 成交量，统一换算为“手” |
| `turnover` | 人民币成交额 |
| `adj_open/adj_high/adj_low/adj_close` | 前复权开高低收 |
| `adjustment_factor` | `adj_close / close`，用于检查复权比例 |
| `source/retrieved_at` | 来源和抓取时间 |

## 质量检查

程序会检查：

- 每只候选ETF是否存在数据，且是否覆盖全部候选代码。
- `symbol + trade_date` 是否重复，行是否按代码和日期排序。
- 未复权与前复权数据的日期集合是否一致。
- 开高低收是否大于0，最高价和最低价是否符合OHLC逻辑。
- 成交量和成交额是否非负，复权比例是否有效。
- 前复权收盘收益是否出现超过配置阈值的异常跳变。
- 每个交易日历开盘日是否有行情，并统计缺失交易日和最长连续缺口。
- 最新一条数据是否覆盖最近一个已经收盘的交易日。

当前阈值在 `configs/default.yaml`。这些阈值是数据质量控制参数，不是策略参数。

```yaml
data:
  history_start: 2012-01-01
  history_min_coverage_ratio: 0.98
  history_max_missing_trade_days: 10
  history_max_missing_gap_days: 10
  history_max_daily_return_abs: 0.22
```

默认从2012年开始保留约14年共同可用历史。更早年份的ETF前复权序列在部分免费数据源中会出现负价格或异常跳变，因此不能为了延长样本而接受不可用的复权价格。

## 运行命令

首次下载全部候选ETF历史：

```powershell
uv run quant-data update-history
```

查看数据摘要：

```powershell
uv run quant-data history-summary
```

重新执行质量检查：

```powershell
uv run quant-data validate-history
```

指定下载区间或检查截止日：

```powershell
uv run quant-data update-history --start-date 2015-01-01 --end-date 2026-10-29
uv run quant-data validate-history --as-of 2026-10-29
```

## 完成的判断标准

以下命令全部成功，并且质量报告状态为 `ok`，才算第四步完成：

```powershell
uv run quant-data update-history
uv run quant-data validate-history
uv run quant-data history-summary
uv run pytest
uv run ruff check .
```

主要输出文件：

- `data/raw/akshare/`：每只ETF的原始未复权与前复权快照。
- `data/processed/etf_daily.parquet`：合并后的标准日线。
- `data/processed/etf_daily_coverage.parquet`：每只ETF的覆盖统计。
- `data/processed/etf_daily_missing_dates.parquet`：缺失的交易日。
- `data/processed/history_quality_report.json`：本次质量检查结果。
- `data/processed/history_metadata.json`：成功更新摘要。
- `data/market.duckdb`：供查询和后续策略读取的 `etf_daily` 表。

## 本步需要理解的最少Python知识

- `DataFrame` 可以理解为带列名的Excel表。
- `merge` 按交易日把两张表拼在一起。
- `groupby` 把数据按ETF代码分组，再分别检查。
- `raise` 表示主动停止程序；数据不合格时不继续运行。
- `pytest` 会自动运行小例子，验证正常数据和错误数据都会得到预期结果。

## 数据边界

AKShare是免费开发数据源，可能调整接口或受到限流。当前结果用于研究和回测基础建设，不代表交易所官方逐笔数据。正式模拟或实盘前，仍需用付费或券商行情进行交叉核验。

当前优先使用东方财富ETF日线接口。如果该接口拒绝连接，程序会尝试新浪未复权ETF日线和腾讯前复权日线作为独立回退源。实际使用的来源记录在 `source` 字段中，混合源也必须通过相同的日期集合和价格质量检查。
