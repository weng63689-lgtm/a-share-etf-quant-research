# 第五步：账户模型与买入持有基准

版本日期：2026年10月29日

## 本步解决什么问题

前一步的 `etf_daily` 只是行情。账户模型把行情转换为真实可追踪的：

- 现金余额。
- ETF持仓份额。
- 持仓成本。
- 现金分红和份额折算。
- 每日现金、持仓市值和总权益。
- 每笔变化对应的事件流水。

本步不生成交易策略，也不连接券商。它先证明后续回测引擎能够正确维护资金和持仓。

## 账户基本规则

当前账户初始资金为50万元，ETF买入数量按100份取整。每一笔事件都写入流水，现金余额等于期初现金加全部现金变动。

每日权益公式：

```text
总权益 = 现金 + Σ(持仓份额 × 未复权收盘价)
```

程序使用 `Decimal` 保存金额和持仓，避免普通浮点数在反复累加后产生明显的分币误差。

买入持有基准不使用卖出，因此不能单独验证T+1。T+1、停牌、涨跌停、佣金、费用、滑点、市场冲击和成交容量已在后续步骤接入；本步展示的早期基准结果仍未扣除这些成本，不能当作策略可交易收益。

## 公司行动

公司行动分为两类：

### 现金分红

现金分红来自新浪ETF累计分红表。程序把累计金额转换为每次分红的增量，例如累计金额从0.10元变为0.35元，则本次每份分红为0.25元。

```text
现金增加 = 持仓份额 × 每份分红
```

现金分红不改变持仓数量和持仓成本。

### 份额折算

免费接口没有统一、完整的ETF份额变动表。程序使用相邻交易日的原始价格收益与前复权价格收益差异识别份额折算，并通过复权因子变化估计份额倍数。

这类事件只有在原始收益与复权收益差异达到5%以上时才进入公司行动表。独立校验会确保事件日期确实存在于对应ETF的日线数据中。

份额折算保持总持仓成本不变，只调整持仓份额和平均成本。由于份额倍数来自市场数据推导，正式模拟交易前仍要用基金公告交叉核对。

## 买入持有基准

本步建立七组基准：

- 六只ETF分别在各自历史首个交易日开盘买入，并按100份取整。
- 六只ETF从共同起始日等权买入，保留无法凑满一手的现金。

买入持有期间不调仓、不卖出、不加入费用，只处理现金分红和份额折算。这样可以用最少变量检查账户记账是否一致。

本次结果如下，仅用于账户模型验证：

| 基准 | 期末权益 | 累计收益 | 最大回撤 |
|---|---:|---:|---:|
| 510050单只 | 1,072,648.00 | 114.53% | -43.15% |
| 510300单只 | 978,240.00 | 95.65% | -44.37% |
| 510500单只 | 1,140,282.81 | 128.06% | -63.27% |
| 512100单只 | 487,975.99 | -2.40% | -50.97% |
| 588000单只 | 415,498.10 | -16.90% | -59.63% |
| 159915单只 | 1,724,360.00 | 244.87% | -69.58% |
| 等权组合 | 485,851.48 | -2.83% | -42.26% |

单只ETF和等权组合的历史区间不同，不能直接按收益排名。较大的回撤也说明这些买入持有基准不是满足20%回撤目标的可交易策略。

## 运行命令

更新公司行动、重建全部基准并执行账户对账：

```powershell
uv run quant-account build
```

查看最新汇总：

```powershell
uv run quant-account summary
```

重新检查已保存的账户质量报告：

```powershell
uv run quant-account validate
```

## 输出文件

- `data/processed/etf_corporate_actions.parquet`：现金分红与份额折算事件。
- `data/processed/buy_hold_snapshots.parquet`：每日现金、市值、权益和持仓份额。
- `data/processed/account_ledger.parquet`：买卖和公司行动流水。
- `data/processed/buy_hold_summary.parquet`：七组基准摘要。
- `data/processed/buy_hold_summary.json`：最近一次成功运行的汇总。
- `data/processed/account_model_quality_report.json`：账户质量门禁结果。

DuckDB中对应表为：

- `etf_corporate_actions`
- `buy_hold_snapshots`
- `account_ledger`
- `buy_hold_summary`

## 验收标准

以下条件必须同时满足：

- 每个日快照的现金和持仓市值之和等于总权益。
- 现金和持仓份额不得为负数。
- 所有买入数量是100份的整数倍。
- 现金不足的买单必须被拒绝。
- 卖出后的现金和已实现盈亏正确。
- 现金分红只增加现金，不改变份额和成本。
- 份额折算只改变份额和平均成本，不改变总持仓成本。
- 账户现金余额与事件流水能够完全对账。

## 本步需要理解的最少Python知识

- 类`Account`表示账户，方法`buy`、`sell`和`mark_to_market`表示账户操作。
- `Decimal`适合保存金额，`float`更适合计算收益率等统计量。
- `LedgerEntry`是不可变的流水记录，发生过的账户事件不应被原地修改。
- 自动测试把小额场景构造成可重复验算的例子，不依赖当天真实行情。

账户模型之后的交易约束已在第六步实现，包括T+1可卖数量、停牌无法成交、涨跌停保守拒单和ETF整手规则。
