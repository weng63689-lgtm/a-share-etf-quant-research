# 第三步基础数据说明

版本日期：2026年10月29日

## 本步完成内容

第三步建立了交易日历、ETF主表和首版策略候选池。数据处理分为原始层、标准化层和策略参考层，策略代码以后只读取标准字段，不直接依赖AKShare返回的中文列名。

## 数据来源

开发阶段使用AKShare：

- 交易日历调用`tool_trade_date_hist_sina`。
- ETF主表优先调用`fund_etf_spot_em`。
- 如果ETF实时接口失败，自动回退到`fund_etf_category_sina`。

免费接口可能因为底层网站调整、网络限制或限流而失效。因此每次更新都会记录实际来源和抓取时间，并保存原始快照。后续接入Tushare或付费数据时，只需增加新的Provider，不修改策略代码。

## 三层数据

1. `data/raw`保存未经修改的抓取快照，用于追溯问题。
2. `data/processed`保存字段统一、去重并通过校验的数据。
3. `data/reference`保存可以进入Git的小型人工核验数据，例如首版候选ETF池。

本地DuckDB数据库位于`data/market.duckdb`，包含`trading_calendar`、`etf_master`和`strategy_universe`三个表。数据库和大体量数据不会上传GitHub。

## 第一版候选池

候选池包含六只境内股票型宽基ETF，覆盖上证50、沪深300、中证500、中证1000、科创50和创业板。选择这些产品是为了建立不同市值和风格之间的轮动研究样本，不是买入建议。

候选池只是研究起点。第四步加入历史行情后，还需要用成交额、上市时间、价差和数据完整性进一步筛选。

## 数据质量检查

程序会检查：

- 交易日期是否重复、排序是否正确、是否覆盖当前日期。
- ETF代码是否为六位数字，交易所是否可识别。
- ETF代码是否重复，价格和成交额是否为负数。
- 全量ETF记录是否达到合理数量。
- 策略候选ETF是否全部存在于ETF主表。
- 候选池是否存在重复代码或不支持的交易所。

任何关键检查失败时，命令返回错误状态，后续任务不得继续使用该批数据。

## 使用命令

```powershell
uv run quant-data update-all
uv run quant-data summary
uv run quant-data validate
```
